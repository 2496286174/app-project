# 横屏游戏 UI 设计文档

适用范围：`Liar's Bar` 局内游戏页。  
目标平台：Android 手机横屏、手机浏览器横屏、桌面浏览器横屏。  
本项目**不做竖屏局内布局**，所有局内设计以横屏为唯一标准。

## 1. 设计目标

这是一个多人横屏桌游界面，设计目标不是网页式信息排版，而是接近原生手机游戏的 HUD 布局：

- 优先保证对局核心信息一眼可读
- 优先保证手牌和操作区可点击、可理解
- 8 人满桌时仍能看清玩家状态
- 横屏手机小高度下不依赖整页缩放硬压布局
- 安卓 WebView 与浏览器表现保持一致

核心原则：

- 不做“把桌面布局缩小到手机里”
- 不做“为了塞下内容而继续加滚动”
- 小高度横屏使用专门的紧凑布局
- 次要信息让位给公共牌区、功能区、手牌区

## 2. 设计基线

### 主设计稿

- `844 x 390`

用于 iPhone 12 Pro 一类手机横屏视口，作为局内 UI 主设计基线。

### 最小兼容尺寸

- `736 x 360`

用于较小安卓横屏设备。低于该尺寸时，继续采用紧凑布局，但不再增加新信息块。

### 大屏扩展尺寸

- `1280 x 720`

用于桌面浏览器、平板、较大安卓横屏设备。大屏只放大留白和舞台感，不改变信息层级。

## 3. 页面结构

局内页面固定为两层外壳：

1. 顶部设置区
2. 主游戏舞台

其中主游戏舞台采用三段结构：

1. 上段：其他玩家信息 + 公共牌区
2. 中段：功能区
3. 下段：手牌区 + 主玩家信息

移动端横屏参考结构如下：

- 顶部：设置区
- 第一排：上方 5 个其他玩家
- 第二排：左 1 个玩家 / 中间公共牌区 / 右 1 个玩家
- 第三排：功能区
- 第四排：左手牌区 / 右主玩家信息

当前代码入口：

- `packages/ui/src/GamePage.tsx`：局内整体布局、横屏 compact 判断和操作区排列。
- `packages/ui/src/cardMetrics.ts`：卡牌、玩家席位、功能区和手牌区域尺寸基准。
- `packages/ui/src/CommunityCards.tsx`：公共牌区。
- `packages/ui/src/PlayerHand.tsx`：手牌区。
- `packages/ui/src/PlayerBox.tsx`：其他玩家席位。
- `packages/ui/src/StatusIcon.tsx`：子弹和手牌状态图标。

## 4. 高度分配

基于 `844 x 390` 主设计稿，建议采用以下高度比例：

- 顶部设置区：`44px`
- 上方玩家区：`92px`
- 中部公共牌区：`118px`
- 功能区：`40px`
- 底部手牌区 + 主玩家信息：`96px`

可接受浮动：

- 顶部设置区：`40px - 48px`
- 功能区：`36px - 44px`
- 底部区域：至少 `88px`

约束规则：

- 公共牌区高度不能低于功能区
- 手牌区高度不能低于公共牌区内容高度的 75%
- 顶部区和功能区只能压缩，不能扩张挤占手牌区

## 5. 宽度分配

### 移动端横屏

- 页面左右安全边距：`8px`
- 左侧玩家位：`72px`
- 右侧玩家位：`72px`
- 中央公共牌主舞台：剩余宽度
- 底部主玩家信息：`104px - 112px`
- 底部手牌区：剩余宽度

### 桌面横屏

- 页面左右边距：`20px`
- 外层最大宽度：`1280px - 1400px`
- 左右玩家位可以增至：`88px - 102px`
- 主玩家信息区可以增至：`136px - 168px`

## 6. 玩家信息设计

### 其他玩家

其他玩家信息只保留：

- 名字
- 席位号
- 状态灯
- 子弹
- 手牌数

不显示：

- 头像
- 冗长身份文案
- “在线/离线”文字

显示规则：

- 上排玩家采用紧凑卡或紧凑条
- 左右两侧玩家优先显示最关键数值
- 行动中的玩家允许有轻提示，但不能占第二行大面积空间

### 主玩家

主玩家信息放在底部右侧，与手牌区同一层级。

只保留：

- 玩家名
- 席位号
- 子弹
- 手牌数

主玩家信息不能独立成大面板压缩手牌区。

当前实现要求：

- 玩家名字行需要和右侧状态指标纵向对齐。
- 子弹、手牌只显示图标和数值，不再显示“子弹”“手牌”文字标签。
- 指标图标来自 `StatusIcon.tsx`，不要在组件里重复内联一套新图标。
- 主玩家信息宽度由布局 token 控制，小横屏保持在 `112px` 左右，避免挤压手牌。

## 7. 公共牌区设计

公共牌区是局内页面的视觉中心。

必须显示：

- 区域标题
- 本轮主牌 / 阶段信息
- 当前公共牌 / 已出牌

规则：

- 中央区域优先给牌面内容
- 空状态时只显示简短提示
- 小高度横屏下卡牌切换到 compact 尺寸

卡牌建议尺寸：

- 标准横屏：`58 x 74`
- 紧凑横屏：`44 x 56`

## 8. 功能区设计

功能区固定在公共牌区下方，不与手牌区混排。

功能区职责：

- 放置“质疑 / 相信 / 出牌 / 加子弹 / 下一局”等主操作

规则：

- 仅保留当前阶段需要的按钮
- 不要出现无效按钮占位
- 按钮优先横向排列
- 小高度横屏下按钮高度压缩，但可点击区域不能小于 `36px`
- 功能区外层不设置整条背景色，不设置横跨牌桌的大宽度底板。
- 功能区宽度由当前按钮内容决定，按钮组居中显示。

按钮规范：

- 常规高度：`40px`
- 紧凑高度：`36px`
- 最小横向间距：`8px`

## 9. 手牌区设计

手牌区固定在底部左侧，是主玩家最优先的交互区域。

规则：

- 手牌始终靠底部主区域显示
- 手牌区不再额外套冗余白盒
- 手牌数量增多时切换为 compact 卡面，而不是整页缩放
- 已选中卡牌只允许轻微上浮，不能遮挡相邻卡牌信息

建议尺寸：

- 普通手牌：`64 x 96`
- 紧凑手牌：`44 x 72`

## 9.1 卡牌尺寸规范

局内所有卡牌必须使用明确尺寸 token，不允许组件自行推导“差不多的大小”。

### 手牌

- 普通模式：`64 x 96`
- 紧凑模式：`44 x 72`
- 牌间距：
  - 普通模式：`6px`
  - 紧凑模式：`4px`

### 公共牌 / 出牌牌面

- 普通模式：`58 x 74`
- 紧凑模式：`44 x 56`
- 牌间距：
  - 普通模式：`8px`
  - 紧凑模式：`6px`

### 规则

- 手牌和公共牌分别使用自己的尺寸 token
- 不允许根据卡牌数量临时改变单张牌尺寸
- 卡牌数量变化时，只调整容器布局和间距，不改单张牌大小
- 所有卡牌容器高度必须反向服从卡牌尺寸，而不是让卡牌去适应容器

## 10. 响应式策略

### 策略 A：大屏横屏

适用：`>= 1024px`

- 使用标准玩家卡
- 公共牌区留更多留白
- 主玩家信息可稍大

### 策略 B：手机横屏标准

适用：`737px - 1023px`

- 使用横屏主稿结构
- 顶部 5 玩家 + 左右 1 玩家
- 公共牌区与功能区明确分层

### 策略 C：手机横屏紧凑

适用：`<= 736px` 或 `max-height <= 500px`

- 所有玩家信息切为 compact
- 公共牌切为 compact
- 头部压缩
- 功能区压缩
- 主玩家区压缩
- 仍然不允许靠整体 scale 解决布局

## 11. 禁止事项

以下做法后续不再采用：

- 把整页当成一个舞台整体缩放
- 用固定桌面比例强塞到手机横屏
- 用滚动条解决核心对局信息溢出
- 给每一块都加厚边框和多层盒子
- 把功能区夹在手牌区和主玩家信息之间
- 为移动端保留桌面级留白

## 12. 实施顺序

后续改版按以下顺序推进：

1. 先锁定横屏结构分区
2. 再锁定每个分区尺寸
3. 再做 compact 组件版本
4. 最后微调颜色、边框、阴影和字重

不要反过来从视觉细节开始调，否则会重复返工。

## 13. 当前结论

本项目局内页的唯一标准是：

- 横屏优先
- 手机横屏优先
- HUD 化信息优先
- 手游式分区优先

后续所有 UI 调整，都应以本文件为准。
